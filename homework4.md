# Module 4 Homework: Why is the primary key important for UPDATE and DELETE?

The primary key, like the `id` column in our `tasks` table, has a different value for every row and never repeats, so it always points to exactly one task. When I write `UPDATE tasks SET done = true WHERE id = 1` or `DELETE FROM tasks WHERE id = 1`, the database is guaranteed to change only that one row, while `WHERE title = 'Buy milk'` changes every row that has this title. In a shared class database it is very easy for two tasks to have the same title, for example two students who both need to buy milk, and then a condition on the title would update or delete all of these rows at the same time. Without a unique id, a user who only wanted to mark one old task as done or remove it could by mistake change or delete other tasks that just look the same, and this lost data could not be brought back. That is why our app always sends `.eq("id", id)` for UPDATE and DELETE, so only the exact task that the user clicked is changed, and Row Level Security also makes sure that it is the user's own task.
